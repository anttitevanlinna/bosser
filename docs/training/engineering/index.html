Agentic Engineering 101

Your engineers use agents.
Now make the work compound.

Six modules on your own codebase. Fix a bug, sharpen a plan, build checks, and run a larger task twice. Each session leaves rules, context, and skills the next one can use.

See what your engineers build

Who it’s for

Software engineers already using coding agents who want to take on harder work and judge the results.

Bring real work

One repository you ship to regularly, working tests, and backlog tasks ranging from a small bug to a larger feature or refactor.

Before we start

Set up Claude Code, install the supplied skills, check repository and pull request access, and pick your first bug.

Your next task starts further ahead.

The work stays in your repository: tested changes, reviewed plans, security decisions, rules, and verification checks. Your engineers practise deciding what to delegate, what to check, and what to preserve for the next run.

Build the engineering practice

Modules 1–3. Short tasks with decisions you can inspect.

01

Getting going + context

Fix a real bug in your own repository. Check what the agent actually read, write the failing test, review the fix, and take it through your pull request and ticket workflow. Capture what worked before you close the session.

Take back to work A tested fix and a personal rules file grounded in the session, ready for the next task.

02

Plan mode, done right

Put a multi-file task through plan mode. Challenge the plan, work through unresolved decisions, and make the agent account for what it missed. Extract task-shaping rules from the planning session and your team’s own tickets.

Take back to work A reviewed plan and reusable rules for turning a vague request into work an agent can execute.

03

Earn the trust

Work in parallel sessions on the same codebase. Review a feature’s access controls and threats, record a hardening decision, and author a test-strategy skill that fits your repository. Test the skill’s weak points before relying on it.

Take back to work A documented security decision and a test-strategy skill shaped by your code and testing conventions.

Let it run. Learn from the result.

Modules 4–6. Two runs of the same task reveal what the system needs.

04

Run the first experiment

Scope a larger task, audit the context and rules you have built, and fill the worst gaps. Let the agent work without step-by-step steering. Keep the result as evidence for the next module, including where it stalled or went wrong.

Take back to work A first long-running experiment on real work, with a record you can inspect.

05

Learn from the test. Run it again.

Find where the first run lost the goal, lost context, or produced plausible but wrong work. Build a check for the dominant failure. Give the agent a reference for the intended result and a plan, then run the same task again.

Take back to work A verification check, a reference, and a plan tested against a second run of the same task.

06

Spot gaps. Build the loop.

Compare the two runs. Decide which gaps need better memory, a stronger check, or a reusable skill. Remove a rule the evidence disproved. Look at how reliably the checks work across runs, then package a recurring task for reuse.

Take back to work An improved working setup and a handoff prompt for building the next skill with checks on its work.

The material keeps working after the session.

Participants get an HTML workbook with exercises, a theory handbook, and practical references. The agents, workflows, and skills they build stay theirs. Training material usage is covered by your agreement.
